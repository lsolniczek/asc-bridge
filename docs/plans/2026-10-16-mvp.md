# Local macOS MVP

## Accepted requirements
- Native local macOS application, one team `.p8` key.
- Agent can add versions and edit description, what's new and promotional text.
- No in-app mutation confirmation. Persistent history for all MCP calls.
- Apple key and JWT never exposed through MCP.

## Decisions
- SwiftPM app bundle; no generated Xcode project or web UI.
- Official MCP SDK 0.12.1 + Hummingbird 2.20.0, locked dependencies.
- Independent stateless transport per HTTP exchange avoids cross-client ID collisions.
- No real Apple credentials available to automated checks; Apple calls use HTTP fixtures.

## Integration findings resolved
- Advertise MCP tools explicitly in initialize; align schema bounds with ASC validation.
- A torn or failed audit append poisons the store until restart; malformed complete
  records fail closed, while a partial trailing write can be recovered safely.
- Tool help uses Apple's `pl` locale and explains matching App Info localizations.
- Each HTTP exchange owns its SDK response state, including concurrent reused IDs.

## Follow-up at larger scale
Startup currently scans the complete local history and retains its projection in
memory. The GUI reads only the newest 500 entries. Streaming recovery and a bounded
in-memory index can be added if long-term history volume warrants them.

## Verified so far

- End-to-end HTTP smoke passed: all six tools, 16 concurrent reused request IDs,
  authentication and Host/Origin checks, invalid requests and 64 redacted audit records.
- Architecture map, shell syntax, Python syntax and Info.plist validation passed.
- `./scripts/check.sh` passed on the final integrated code.
- Release `.app` bundle passed strict codesign verification and the same HTTP smoke.
- Onboarding view rendered and inspected without starting Keychain or ASC requests.
- Fresh read-only review of the complete empty-tree diff: no material findings.
  Non-blocking: unrecognized protocol methods are recorded as `unknown` rather

Live Apple requests and the import/use of a real ASC private key are deliberately
left for the user's in-app connection test; no real private key was available to
or inspected by the agent.
